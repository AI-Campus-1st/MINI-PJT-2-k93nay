## 1. 대상 청중과 핵심 의사결정 정의

* 주요 청중: SH공사 청년주택본부 및 핵심 의사결정권자
* 핵심 결정: 서울 도심 내 노후 저층 주거지를 매입하여 '모듈러 기반 자율주택정비사업' 방식으로 청년 공공임대주택을 공급할 때, 한정된 공공 예산을 동대문구 내 어느 행정동(필지군)에 최우선 투입할 것인가?

### 가설 및 SCQA 스토리라인 설계

* S (Situation - 상황): 청년 매입임대주택 사업은 도심 내 청년층 주거 안정을 달성하기 위한 SH공사의 핵심 핵심 사업이나, 완공 후 수요 예측 실패로 장기 공실이 발생할 경우 공사 재정에 즉각적인 타격을 입힐 수 있습니다.

* C (Complication - 문제): 선행 미니프로젝트 1단계 분석을 통해 '동대문구'를 최우선 유망 자치구로 도출했으나, 기존 주민등록인구 데이터는 밤에 잠을 자는 상주인구만 집계하므로, 주간 활동 중심인 청년층의 실시간 유입 규모 및 공간 활용 패턴을 반영하지 못하는 치명적인 한계를 지닙니다.

* Q (Question - 질문): 동대문구 관할 14개 행정동 중 자율주택정비에 최적화된 물리적 노후 인프라 상수를 만족하면서도, 실제 청년 활동인구의 절대 유입량(Volume)과 집중 밀도(Density)가 동시에 가장 높아 공실 리스크를 제로(0)로 수렴시킬 요충지는 어디인가?

* A (Answer - 해답): 실시간 이동통신 기지국 추계 데이터인 '서울 행정동별 생활인구' 60일 장기 시계열 API를 확보하고, 최고점 후보지 대비 1,000점 만점으로 정규화(Scaling)한 2차원 교차 검증 매트릭스 모델을 구축하여 '휘경2동, 청량리동, 전농1동 등 회기역-청량리역 중심의 교통허브 복합 배후지이자 쿼드러플 대학교 거점의 행정동'을 공실 제로의 최종 최우선 매입 대상지로 확정합니다.

## 2. 데이터 수집 (Data Collection Pipeline)    

### 사용 API 및 인프라 마스터 데이터셋 명세

   1. 서울시 행정동 단위 서울 생활인구(내국인) Open API

   * 출처 및 방식: 서울 열린데이터광장 (Spop250mLocalResdDong 표준 API 연동)
      * 수집 범위·기간: 가용 최신일 기준 과거 60일 전체 범위 시계열 데이터 수집
      * 수집 건수: 총 201,600건 (60일 시계열 × 24시간 축 × 동대문구 14개 행정동 마스터)
      * 비즈니스 용도: 시간대별 2030 청년 절대 유입수 및 총 유동인구 대비 점유 비중 도출

   2. 미니프로젝트 1단계 저층 주거지 인프라 마스터셋 (housing_db 연동)

   * 출처: 국가공간정보포털(도로구간), 국토교통부(건축물대장 표제부), 통계청
      * 공간 인프라 고정 상수: 동대문구 관할구역 정규화 면적(km²)당 노후주택수(1200.35), 면적당 좁은도로수(57.59), 면적당 자율주택대상수(1256.26)
      * 비즈니스 용도: 생활인구 수요 축과 물리적 정비 요건 축을 결합하는 가중치 상수로 활용
   
### 엔지니어링 문제와 해결 (Data Pipeline Stability)

   * API 한도 초과 및 서버 차단(Rate Limit) 대응:
      대량의 시계열 데이터를 24시간 축으로 연속 호출할 시 일일 트래픽 초과 및 방화벽 차단 리스크가 발생합니다. 이를 방지하기 위해 urllib3.util.retry를 적용한 독립 공통 HTTP 세션 호출기(client.py)를 개발했습니다. 429, 500대 에러 발생 시 자동 지수 백오프를 작동시키고 요청 간 time.sleep(0.3) 안전 대기시간을 바인딩하여 60일치 데이터의 무손실 수집에 성공했습니다.

   * 5일 전 당일 자료만 조회되는 API 정책 제약 우회:
      서울시 오픈 API가 제공하는 최신 데이터 조회 제약을 해결하기 위해, 로컬 백업 폴더(data/)에 기 저장된 파일 데이터가 존재할 경우 중복 수집을 패스하고 오직 누적되지 않은 일자만 자동 계산해 페이징 호출하는 '증분 순회 수집 엔진'을 구축하여 수집 효율성을 극대화했습니다.

## 3. 아키텍처 및 DB 설계 (Architecture & Warehouse)

### 데이터 순수 단방향 디렉터리 아키텍처
본 시스템은 화살표가 오직 한 방향으로만 흐르는 물리적 계층 분리를 엄수합니다. 화면 계층이 API를 임포트하거나 DB에 쓰기 연산을 수행하는 아키텍처적 결합을 원천 차단했습니다.

```text
┌─────────────────────────┐             ┌─────────────────────────┐               ┌─────────────────────────┐
│ ① 수집 계층 (Collector)  │    적재     │  ② 저장 계층 (Warehouse) │     조회      │ ③ 화면 계층 (Dashboard) │
│  python -m collector    │ ─────────▶ │  MariaDB / MySQL DB      │  ◀─────────  │ streamlit run app/...  │
│  (API 수집/정제/UPSERT)  │   (쓰기)    │  (원본 Layer ➔ 마트)    │    (읽기)     │  (캐싱 전용, 읽기전용)   │
└─────────────────────────┘             └─────────────────────────┘               └─────────────────────────┘
```

### 의사결정 집계 데이터 마트 스키마 명세 (db/schema.sql)

* 수집 원본 계층 (seoul_living_pop_raw): 24시간의 시계열 API 로우 데이터를 있는 그대로 보존하는 버퍼창고 (PRIMARY KEY: base_date, hour, dong_code).
* 집계 마트 계층 (mart_youth_housing_priority): 대시보드의 연산 병목을 제거하기 위해 시간축을 일평균 레벨로 선행 압축 집계한 대시보드 전용 고성능 마트 테이블.

```py
CREATE TABLE mart_youth_housing_priority (
    base_date               VARCHAR(8) NOT NULL,   -- 수집 기준일자 (Index)
    dong_code               VARCHAR(8) NOT NULL,   -- 8자리 행정동코드
    dong_name               VARCHAR(50) NOT NULL,  -- 행정동명
    avg_youth_pop           DOUBLE,                -- 일평균 청년 생활인구 (절대 수요)
    youth_occupancy_rate    DOUBLE,                -- 지표 1: 청년 생활인구 점유율 (상대적 밀도)
    final_volume_score      DOUBLE,                -- 지표 2: 미니프로젝트1 가중치 반영 1,000점 정규화 규모 점수 (절대 수요 규모)
    final_priority_score    DOUBLE,                -- 지표 3: 상대밀도 X 절대규모 1,000점 만점 종합 점수 (최종 점수)
    PRIMARY KEY (base_date, dong_code)
);
```


### 융합 파생지표 정의 및 스케일링(Scaling) 산식
청중인 SH공사 경영진의 직관적인 대시보드 스크리닝을 돕기 위해 관할 구 내 최고점 후보 지역을 1,000점 만점 기준으로 변환하는 상대 정규화 연산을 마트 빌드 단계에서 사전 수행했습니다.

   1. 청년 생활인구 점유율 (youth_occupancy_rate) [Density - 상대 밀도 지표]

   * 산식: 일평균 2030 청년 생활인구 수 (youth_pop) ÷ 일평균 총 생활인구 수 (total_pop)
      * 비즈니스 의미: 해당 동 내 청년층의 집중도로서 공급 후 수요 미스매치를 방어하는 공실 차단 축입니다.

   2. 절대 수요 인프라 가중치 점수 (final_volume_score) [Volume - 절대 규모 지표]

   * 산식: (해당 동의 가중치 원점수 ÷ 기준일자 내 최고 동의 가중치 원점수) × 1000
      * 원점수 공식: (청년인구 * 면적당 노후주택수 * 0.34) + (청년인구 * 면적당 좁은도로수 * 0.33) + (청년인구 * 면적당 자율주택대상수 * 0.33)
      * 비즈니스 의미: 미니프로젝트1의 3대 물리적 정비 제약 요건에 청년 절대 수요를 조인한 뒤 최고점을 1,000점으로 맵핑해 단위 혼선을 제거한 사업 규모 지표입니다.

   3. 최종 유망도 종합 스코어 (final_priority_score) [최종 의사결정 축]

   * 산식: (해당 동의 종합 원점수 ÷ 기준일자 내 최고 동의 종합 원점수) × 1000
      * 종합 원점수 공식: 원점수 기반의 final_volume_score × youth_occupancy_rate
      * 비즈니스 의미: 절대 규모와 상대 밀도를 공간 결합하여 매트릭스 상의 1사면 최상단 요충지를 단 하나의 인덱스로 짚어내는 최종 스코어입니다.
   
### 파이프라인 무결성 및 성능 최적화 교정

* MariaDB 파서 버그 우회 및 UPSERT 안정화: 대량 연산 시 발생하는 락을 방지하고자 temp_dong_daily_summary 및 temp_raw_scores 단계별 임시 테이블 연산을 설계했습니다. 
* 명시적 인덱스 튜닝: 대시보드의 날짜 슬라이더 필터링 연산을 지원하기 위해 조회 기준 컬럼인 base_date에 명시적 복합 인덱스(idx_mart_base_date)를 설정하여 디스크 I/O를 전면 최적화했습니다.

## 5. 핵심 인사이트 (Data-Driven Insights)

### 시계열 데이터 교차 검증을 통한 통찰 도출

   1. 거주하는 인구와 활동하는 인구의 결정적 미스매치
   * 기존 주민등록 기반 인구로는 해당 행정동의 교통/입지적 특성에 따른 주택에 관한 실 수요를 가진 유동인구를 파악하는데 한계가 있었기 때문에, 60일간의 시계열 생활인구 빅데이터를 분석하게 되었습니다. 
   * 그 결과 상대적 청년 집중 밀도(점유율)는 청량리동, 휘경2동, 회기동 등이 최고 46%에 육박한 반면, 타 행정동은 23~40%에 머무르며 최대 2배의 격차를 보였습니다.

   2. 물리적 우수지와 수요 우수지의 불일치 현상 발굴
   * 1단계 공간 분석 자산인 노후도와 도로 협소도 등 하드웨어 요건에 청년인구의 절대 규모만 반영했을 때는 휘경2동, 전농1동 및 장안1동 일대가 유망 필지로 분석되었습니다. 
   * 그러나 시계열 데이터와 교차 조인한 결과, 전농1동, 장안1동 등의 동들은 청년 비중이 타 행정동 대비 낮아 '여건은 우수하나, 공실 리스크 위험이 있는' 행정동으로 스크리닝되었습니다. 
   * 반면에 청량리동, 회기동 등은 시계열 데이터와 교차 조인한 결과, '절대 규모로는 타 행정동에 비해 상대적으로 낮으나 청년 비중이 높아, 절대 규모에 비례한 주택공급 시 공실 리스크 위험이 낮은' 행정동으로 스크리닝 되었습니다.

   3. 최종 의사결정: 공실 제로 1사면 요충지 동 확정
   * 최고점 스케일링 기반의 최종 유망도 종합 스코어를 연산한 결과, 1호선·경의중앙선 휘경역(회기역)과 청량리역의 핵심 배후 주거지이자 시립대학교, 경희대학교, 한국외국어대학교, 고려대학교의 인구 흐름이 모두 교차하는 권역인 '휘경2동'이 종합 점수 1,000점 만점 영역에서 최종 탑-픽(Top-Pick) 매입 대상지로 도출되었습니다. 
   * 이 지역은 저층 노후 주거지가 밀집해 필지 확보가 쉬울 뿐만 아니라, 방학 및 비수기 구간에도 청년 생활 유입 활동 밀도가 견고하게 유지되어 청년주택공급 연계 시 공실률 0%를 달성할 수 있는 최적의 요충지입니다.
